# 定时采集任务说明（换机重建设备用）

仓库里保存这份文件，是为了让「定时采集」这项能力可以跟着仓库走。
**任务本身不会自动跟过去**——WorkBuddy 的自动化是绑定在这台机器上的本地任务，换电脑必须在新的 WorkBuddy 里重新建两条。

采集范围分两类：**讲座与活动（主线）**，以及**学生事务通知（补充：奖助学金、教务学籍、放假校历、就业实习、竞赛报名、生活服务）**。
宣传提醒类（防诈骗、消防演练、安全教育）一律不收，口径见下。

## 两条任务

| 名称 | 时间 | rrule |
| --- | --- | --- |
| 讲座雷达 · 午间采集（12:30） | 每天 12:30 | `FREQ=DAILY;BYHOUR=12;BYMINUTE=30` |
| 讲座雷达 · 晚间采集（20:30） | 每天 20:30 | `FREQ=DAILY;BYHOUR=20;BYMINUTE=30` |

> 两条任务的 prompt **完全相同**，只是时间不同。rrule 的 `BYHOUR` 不支持逗号列表，所以必须拆成两条。

## 重建步骤

1. 在新电脑的 WorkBuddy 里打开本项目目录（或任意目录）
2. 新建自动化 → 重复日程 → 按上表填时间和 rrule
3. 把下面的 prompt 整段粘进去，**只改第一行的项目路径**
4. 启用，确认状态为 ACTIVE

## Prompt 正文（复制这段）

```
在 <新电脑上本项目的绝对路径> 目录下执行一轮广东工业大学信息采集，完成后自动发布到 GitHub Pages。

本轮分两类内容，**讲座与活动是主线，学生事务是补充**：
- kind=activity：讲座 / 学术报告 / 学术论坛 / 研讨会 / 学术会议 / 宣讲招聘 / 学科竞赛说明会。每轮必须完成这类采集。
- kind=notice：与学生切身相关、有时效或需要办理的事务通知。做完 activity 采集后再顺带收集，每轮最多 8 条。

【一、讲座与活动（主线，必收）】
- 只收真要参加的活动；招生简章、名单公示、纯行政通知不收。
- 优先参与地点在广工校内的：大学城、东风路、龙洞、番禺、揭阳、沙河校区，或工学一号馆/二号馆/四号楼、大讲堂、学术报告厅、图书馆等校内场所。校外会议只在明确面向我校研究生时收录。
- 重点面向群体：全校学生、自动化学院学生、信息工程学院学生（含研究生）。物理与光电工程学院已不在采集范围。
- 能拿「学术条」或「实践条」的，必须在 credit 字段注明。
- **收录门槛（宁缺勿滥）**：
  · **其他学院主办的一律不收**（自动化学院、信息工程学院之外，例如轻工化工学院的「轻化名师讲坛」、管理学院的年会、经济学院的论坛）。校级部门（研究生院、学生工作处、教务处、通识中心、分析测试中心）和学会主办的不受此限。
  · **讲座必须能明确说出「面向谁」或「能拿什么条」**，两者都没有的不收 —— 原文既没写面向对象、也没写能拿学术条 / 实践条的，直接跳过。
  · 判断依据是原文，不要靠推测。查不到就说明它不够格，不收。

【二、学生事务（补充，每轮最多 8 条）】
只收下面六类，且必须同时满足两个条件：与学生本人有关 + 有时效或需要办事（报名、提交、办理、缴费、截止、时间节点）。
1. 奖助学金：国奖、学业奖学金、助学金、助学贷款、困难认定、评优评选、补助
2. 教务学籍：选课与补退选、缓考重修补考、成绩、学籍异动、开题中期答辩、查重、培养方案
3. 假期校历：放假、返校、调课停课、开学报到、校历调整
4. 就业实习：实习、三方协议、派遣档案、就业手续
5. 竞赛报名：学科竞赛的报名通知与截止时间
6. 生活服务：医保参保缴费、宿舍调整、校园卡办理、体检、报销

**明确不收**（哪怕推送很多）：防诈骗、反诈、消防演练、安全教育、警示教育、倡议书、点赞投票、转发征稿、读后感、节电节水这类宣传提醒。
判断标准只有一条：这条信息是否要求学生「去办一件事」或「记住一个时间节点」。只是提醒「注意 / 警惕 / 参与」的，一律不收。

【抓取入口，按优先级】
1. https://www.gdut.edu.cn/index/xsdt.htm （学术动态，卓越大讲堂在此）
2. https://www.gdut.edu.cn/index/tzgg.htm （通知公告，事务类多在此）
3. https://automation.gdut.edu.cn/tzgg.htm 与 https://automation.gdut.edu.cn/xygk/xwdt.htm （自动化学院）
4. https://xxgcxy.gdut.edu.cn/kxyj/xsbg.htm 与 https://xxgcxy.gdut.edu.cn/ （信息工程学院，含「信研博学」研究生学术论坛）
5. https://tsjy.gdut.edu.cn/ （通识教育中心，论坛类常发学术条）
6. https://yjs.gdut.edu.cn/ （研究生院：奖助、培养、开题答辩）
7. https://xsc.gdut.edu.cn/ （学生工作处：奖助、宿舍、医保）
8. https://jwc.gdut.edu.cn/ （教务处：选课、考试、校历）
9. 关键词检索最多 6 条：广东工业大学 讲座预告；广东工业大学 学术报告 通知；卓越大讲堂；广东工业大学 学术论坛 研讨会 通知；自动化学工e站 讲座；信息工程学院 学术报告

【录入纪律】
- 禁止臆造讲座、主讲人、日期、学分、截止时间。日期不确定就留空，time_text 照抄原文。
- 用 python scripts/lecture_hub.py add data/patch-YYYYMMDD-HH.json 录入，字段：title, speaker, date, time_text, location, org, source, url, summary, credit, audience, college, tags, kind, deadline。
- kind：讲座与活动一律 `activity`，事务通知一律 `notice`。
- deadline：通知类**必填**，填报名 / 提交 / 办理的截止日期（YYYY-MM-DD）；原文没有明确截止日期就留空，不要编。
- date：活动填举办日期；通知类填关键日期（如放假开始日），没有就留空。
- category 不用填，程序按 kind 自动归类。真要指定时：activity 用 学术报告/学术会议/论坛会议/宣讲招聘/学科竞赛；notice 用 奖助学金/教务学籍/假期校历/就业实习/竞赛报名/生活服务。
- college 只表示「面向」学院，**只有原文明确写「面向自动化学院 / 面向信息工程学院」时才填**。主办单位、品牌栏目、来源域名都不能作为依据 —— 那些由 host_college 自动识别。
- 面向全部研究生（或全校师生）的：audience 填「研究生」，**college 留空** —— 看板会自动把它同时计入两个学院的研究生入口。只有明确只面向某一个学院时才填 college。
- 典型反例：信息工程学院主办的「信研博学」研究生学术论坛，报名对象写的是「全校在读硕士、博士研究生」→ college 必须留空。判断依据是报名对象，不是主办方是谁。
- 无新增就如实说「本轮无新增」，不要拿非讲座类通知凑数。

【发布】
cd 到项目目录后执行 bash scripts/publish.sh，数据与看板会推到 GitHub 并自动触发 Pages 更新。

【汇报】
一句话说明：本轮新增几条（讲座活动 X 条、学生事务 Y 条）、库里共几条、有没有带学分条的新讲座或临近截止的待办。
```

## 注意

- **同一时间只让一台电脑跑采集**。两台都跑会出现同一条讲座各录一次、各自推送、互相覆盖。
- 换机后如果只想在日常用的那台跑，把旧机器的两条任务**暂停**（不是删除，留作备份）。
- `publish.sh` 已经内置「先 fetch + rebase 再推送」，所以偶尔两边都动过也能自动合上；但数据文件冲突时仍会停下来报错，需要手动处理。
